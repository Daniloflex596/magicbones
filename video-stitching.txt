Video Stitching / Bridging
When bridging two videos together with a seamless AI-generated transition clip (extracting the last frame of Video 1 and the first frame of Video 2):

1. Asset Retrieval Quirks
higgsfield_attachments_list ONLY returns files the user uploaded directly. It does not return generated videos.
To access existing generated videos for stitching, ask the user to provide the Asset URLs (e.g., https://higgsfield.ai/asset/video/<job_id>) or the Job IDs directly.
Use higgsfield_job_status to resolve those Job IDs into playable video URLs.
2. Frame Extraction
Download the videos and use ffmpeg to grab the anchors:

Last frame of Video 1: Use ffprobe to get duration, then ffmpeg -y -i v1.mp4 -ss <duration - 0.5> -vframes 1 -update 1 -q:v 2 start.jpg. Do not use -sseof — it fails on short/VFR clips resulting in 0-byte or invalid frames.
First frame of Video 2: ffmpeg -y -i v2.mp4 -vframes 1 -update 1 -q:v 2 end.jpg Upload both frames via higgsfield_upload to get their media IDs.
3. Model Quirks & Selection
The default documentation for model capabilities contains inaccuracies regarding end_image support. Enforce these rules:

Kling 3.0 (kling3_0): SUPPORTS both start_image and end_image. Use this for high-quality bridging. Set duration to a minimum of 3 seconds.
Seedance 2.0 (seedance_2_0): DOES NOT support end_image. However, you can pass both extracted frames as image roles and prompt: "One continuous uncut shot. Must start exactly with image 1 and must end exactly with image 2." Duration must be at least 4 seconds.
Wan 2.7 (wan2_7): DOES NOT support end_image. Passing the end frame as an image role provides a stylistic target but does NOT guarantee a hard structural lock to that frame at the end of the clip. Prompt steering ("Must end exactly with image 2") helps but is not absolute.
Kling 2.6 (kling2_6) and Seedance 1.5 (seedance1_5): Support both start and end frames natively.
4. Frame Extraction Strategy
Higgsfield job URLs return videos, not images. To get the frames, you must download the videos using a tool like curl and extract the exact frames using ffmpeg, then upload those frames as media_input.
Extract the last frame of V1: ffmpeg -y -i v1.mp4 -ss <duration - 0.5> -vframes 1 -update 1 -q:v 2 last_frame.jpg
Extract the first frame of V2: ffmpeg -y -i v2.mp4 -vframes 1 -update 1 -q:v 2 first_frame.jpg
Upload the extracted frames using higgsfield_upload before passing their IDs to the model.
5. Generation Payload
Submit the bridge generation via higgsfield_generate using the exact media_input structure:

json

{
  "model": "kling3_0",
  "params": {
    "duration": 3,
    "prompt": "One continuous uncut shot",
    "medias": [
      { "role": "start_image", "data": { "id": "<upload_id_1>", "type": "media_input" } },
      { "role": "end_image", "data": { "id": "<upload_id_2>", "type": "media_input" } }
    ]
  }
}
6. Video Concatenation
When the bridge generation is complete, use ffmpeg concat to losslessly stitch the three clips (V1 -> Bridge -> V2) into a single final video:

Re-use the V1 and V2 clips that were already downloaded during the frame-extraction phase (do not re-download them).
Download the generated bridge clip locally.
Create a list.txt file containing the paths, one per line: file '/path/to/clip.mp4'
Run ffmpeg -y -f concat -safe 0 -i list.txt -c copy final.mp4 to merge without re-encoding.
Upload final.mp4 via higgsfield_upload to deliver the result.
For N-clip chains (e.g. 3 clips = 2 bridges): Fire all bridge generation jobs in parallel rather than sequentially. Combine them all into the single concat operation at the end.

7. Audio Blending via Promoted Audio Inputs
When the user wants the bridge clip to seamlessly carry the audio from V1 into V2:

Extract the last 1s of V1's audio: ffmpeg -y -sseof -1 -i v1.mp4 -vn -acodec pcm_s16le audio1.wav
Extract the first 1s of V2's audio: ffmpeg -y -i v2.mp4 -t 1 -vn -acodec pcm_s16le audio2.wav
Upload both wav files via higgsfield_upload.
In Seedance 2.0, pass audio via the top-level input_audio param (NOT role: "audio" in medias — that triggers HTTP 500). Example: params: { input_audio: { id: "<uuid>", type: "media_input", url: "..." } }
Add prompt steering: "@Audio1 blends into @Audio2 in one continuous uncut sound logically."
